# 0.4: New note diagram

The user is on https://studies.cs.helsinki.fi/exampleapp/notes, writes a note into the text field and clicks **Save**.

```mermaid
sequenceDiagram
    participant browser
    participant server

    Note left of browser: User writes a note and clicks "Save". The form has method="POST" and action="/new_note", so the browser submits it as form data (note=...)

    browser->>server: POST https://studies.cs.helsinki.fi/exampleapp/new_note
    activate server
    Note right of server: Server pushes { content, date } into the in-memory notes array
    server-->>browser: 302 Found, Location: /exampleapp/notes
    deactivate server

    Note left of browser: The redirect makes the browser reload the notes page

    browser->>server: GET https://studies.cs.helsinki.fi/exampleapp/notes
    activate server
    server-->>browser: HTML document
    deactivate server

    browser->>server: GET https://studies.cs.helsinki.fi/exampleapp/main.css
    activate server
    server-->>browser: the css file
    deactivate server

    browser->>server: GET https://studies.cs.helsinki.fi/exampleapp/main.js
    activate server
    server-->>browser: the JavaScript file
    deactivate server

    Note left of browser: The browser starts executing main.js, which fetches the JSON from the server

    browser->>server: GET https://studies.cs.helsinki.fi/exampleapp/data.json
    activate server
    server-->>browser: [{ "content": "HTML is easy", "date": "2023-1-1" }, ..., { "content": "<the new note>", "date": "..." }]
    deactivate server

    Note left of browser: The browser executes the callback that renders the notes, now including the new one
```

In total the form submit causes five HTTP requests: one POST and, after the redirect, four GETs.
